RFQ BID TRACKER - SPEC
======================

User:     Israel Blackman, Discover Group (Brooklyn, NY)
Purpose:  See each request at a glance and decide whether or not to bid.
Principle: Include all information needed for a bid / no-bid decision, and nothing extra.
Status:   Phase 1 (display) is built and runs on LIVE data (NYC and SAM.gov feeds). The page
          never shows made-up data: no feed = "No data". NYS feed is a stub (see section 3).


1. MAIN VIEW - TABLE COLUMNS
----------------------------
Eleven columns, left to right. Each is sortable except Status, RFQ doc and Details.

 #  Column          Notes
 1  Status          Dropdown per row (chosen over one-click icon buttons to avoid
                    accidental clicks). Default "New" = not yet marked.
                    One status per request; icon shown in each option:
                      star   Interested
                      pencil Bidding (preparing the bid)
                      check  Bid submitted
                      cross  Pass / not applicable
                    Row tint: passed rows dimmed; interested / bidding / submitted get a
                    colored left edge.
                    Saved in the browser (localStorage) for now: NOT shared across
                    devices or users, and lost if browser data is cleared or the
                    computer fails. Needs a backend or a file store (see 2c).
 2  Request         Title of the request (agency shown beneath). ALL-CAPS titles from
                    agencies are tidied to Title Case (acronyms kept upper case).
 3  Category        Type of work. NYC: City Record category. SAM.gov: "NAICS <code>".
 4  Eligibility     Chips listing everything the RFQ requires to bid (Israel decides); "Not read" if unknown.
                    Compares the RFQ's requires[] against the company profile
                    (COMPANY.holds in data.js). "No data" when the profile is empty
                    (currently the case: Israel has not provided it) or the RFQ's
                    restriction could not be read. Sortable. Not-eligible rows are
                    still shown. AI-read rows say "AI-extracted, please verify."
 5  Posted          Date the request was posted.
 6  End date        Bid due date plus due time and time zone. Due dates more than 3 years
                    out are treated as placeholders: shown as "No real due date".
 7  Days left       Days from today to the end date. "Closed" if past, a dash if no real
                    due date. Colored: 7 or fewer = red, 14 or fewer = orange, else green.
 8  Municipality    Federal / State / Local badge.
 9  RFQ doc         "Open RFQ" link to the solicitation (NYC City Record page or SAM.gov
                    notice).
10  Est. value      Dollar value, always labelled with where it came from, in this order:
                    a) Published by the agency (contract amount in the notice).
                    b) Stated in the notice: amount read by AI, with the quoted sentence
                       under "Where from". Only kept if the quote really contains the
                       amount. Flagged "AI-extracted, please verify".
                    c) Estimate from similar past awards (NYC only): median with a
                       25th-75th percentile range, from competitively bid City Record
                       awards of the last 3 years (renewals, amendments, noncompetitive
                       excluded). Tiers: same agency + category + title keywords;
                       same category (any agency) + keywords; same agency + category
                       with no keyword match ("broad estimate"). Needs at least 3
                       awards. "How estimated" lists the method and 5 recent examples.
                    d) "Not published" when none of the above exists.
                    DEFAULT SORT: descending by this value; unknown values last.
11  Details         ONE merged column. Top to bottom:
                    1) region
                    2) "Bid factors" box (see below)
                    3) chips: "Restricted: ..." (red), Amended, warnings, plain
                       requirement chips (e.g. selection method, mandatory pre-bid)
                    4) scope summary, cut at 220 characters with Show more / Show less
                    5) "Show all requirements (n)" toggle that opens a full-width row of
                       the key "shall" statements with section/page refs and a link to
                       the full RFQ. Only shown when shall[] is not empty.
                    AI-read rows are labelled "AI-read, verify".

Bid factors (box at the top of Details)
 Chips for facts that commonly decide bid / no-bid. Detected by keyword (FACT_RULES in
 index.html) from the scope, "shall" text, requirement chips and restriction. Hover a chip
 to see the source sentence. Colors:
   red   = gate: TSA-checked workers, security clearance, background checks /
           fingerprinting, license / certification
   amber = cost / effort: bonds, insurance minimums, prevailing / living wage, mandatory
           site visit / pre-bid, 24/7 or after-hours
   blue  = info: set-aside / preference, past performance / references, multi-year term
 Bonds, pre-bid meetings and background checks are chips, not dedicated or filterable
 fields (decided).

Toolbar and behavior
 - Search box (see below).
 - Filters: Municipality (All levels / Federal / State / Local), Category, Status (All /
   New / Interested / Bidding / Bid submitted / Passed).
 - "Hide closed" (on by default).
 - "Hide flagged" (on by default): hides notices with a warning, i.e. a placeholder
   deadline (2099 or later, or more than 3 years out) or posted over a year ago.
 - Count line: "n of N requests", source(s) and when the data was last updated.
 - No paging: all matching requests are always shown.
 - Click a header to sort; click again to reverse.
 - Narrow screens (900px or less): each request becomes a labelled card.

Search
 Free-text words must all match (AND) anywhere in the request, including dates and values.
 Plus optional structured pieces:
   numbers:   "value > 300k", "value 100k-500k", "days left <= 7", "days left: 22".
              Field names: value/price/amount/cost, days left, due/ends/closes/deadline,
              posted/date. Operators: > < >= <= = != ; k/m/b suffixes; ranges.
   dates:     "due < 2026-12-31", "posted >= 2026-10-01" (a bare date means due date).
   column:    "municipality: local", "category: construction", "agency: ...",
              "request: ...", "region: ...", "status: ...", "eligibility: <requirement>".
              "eligibility: determined" shows only rows whose eligibility is known (not
              "No data"); "eligibility: yes" / "eligibility: no" filter by result.
   status:    keywords interested / bidding / submitted / passed filter by bid status.
   "no due date" finds placeholder or missing deadlines.
   A bare column name (e.g. "municipality") does not narrow the results.

3. DATA INTEGRATION
-------------------
How it works: node scripts write live-*.js files; index.html loads whichever exist
(live-sam.js, live-nyc.js, live-ny-state.js) and merges them. Re-run a script to refresh;
there is no scheduler yet. The data shape is documented at the top of data.js.

 - NYC City Record (fetch-nyc.js): LIVE. Open Procurement solicitations from NYC Open
   Data, no key needed. Optional AI read (needs ANTHROPIC_API_KEY): stated amount,
   requires, scope, key "shall" points. Then similar-award value estimates.
   Run: node fetch-nyc.js [--max 500]
 - SAM.gov Opportunities (fetch-sam.js): LIVE. Solicitations and combined
   synopsis/solicitations posted in the last 30 days. Needs SAM_API_KEY (free; environment
   only). Optional AI read as above. Run: node fetch-sam.js [--days 30 --max 300]
 - NYS Contract Reporter (fetch-ny-state.js): NOT LIVE. The conversion, filters and file
   writing are done, but there is no known API; waiting for a reply from the Contract
   Reporter. Can be tested with: node fetch-ny-state.js --from-file notices.json
 - Not started: USAspending.gov (pricing / competitor context), SAM.gov Entity API
   (vendor registrations), DIBBS and eBuy (need logins or scraping). Add one at a time.
 - Secrets and generated files stay out of git (.gitignore): keys, live-*.js,
   ai-usage.log, ai-cache.json.

Things that trip up newcomers (from notes)
 - Deadlines are date, time and time zone, plus the agency's clock rules.
 - Solicitations change by amendment: diff and notify.
 - An RFQ may go only to GSA Schedule holders or a short list of vendors.
 - Lowest price does not always win; technical acceptability and responsibility count.
 - Past performance / CPARS ratings matter to repeat buyers.
 - Sources-sought notices are early signals.
 - Teaming agreements and subcontracting are central; model partners.

RFQ BID TRACKER - SPEC
======================

User:     Israel Blackman, Discover Group (Brooklyn, NY)
Purpose:  See each request at a glance and decide whether or not to bid.
Principle: Include all information needed for a bid / no-bid decision, and nothing extra.
Phase 1:  Build the app and its display (sample data). Data integration comes after.


1. MAIN VIEW - TABLE COLUMNS
----------------------------
 0  Status          (leftmost) Dropdown per row (chosen over one-click icon buttons
                    to avoid accidental clicks). Default "New" = not yet marked.
                    One status per request; icon shown in each option:
                      star   Interested
                      pencil Bidding (preparing the bid)
                      check  Bid submitted
                      cross  Pass / not applicable
                    Row tint: passed rows dimmed; interested / bidding / submitted get a
                    colored left edge. Status filter above the table (All / New /
                    Interested / Bidding / Submitted / Passed).
                    Saved in the browser (localStorage) for now: NOT shared across
                    devices or users. Needs a backend when data integration happens.
 0b Can we bid?     (right after Request) Eligible / Not eligible (needs: ...) / Unclear.
                    Compares the RFQ's requires[] against the company profile. Sortable.
                    Not-eligible rows are still shown (sort by this column to group them).
                    Currently uses an INVENTED company profile.
 #  Column          Notes
 1  Request         Title of the request (agency shown beneath).
 2  Category        Type of work, e.g. janitorial, security, HVAC.
 3  Posting date    Date the request was posted.
 4  End date        Bid due date. Also show due time and time zone.
 5  Days left       datediff(today, end date), in days. Closed requests are marked "Closed".
 6  Municipality    Federal / State / Local.
 7  RFQ doc         Link to the RFQ / solicitation document.
 8  Est. value      Dollar value. DEFAULT SORT: descending. Unpublished values sort last.
 9  Details         ONE merged column (no separate scope column). Top to bottom:
                    1) region, 2) flag chips, 3) one-line scope summary,
                    4) "Show all requirements (n)" toggle that expands a full-width row of
                    the key "shall" statements with section/page refs.
                    Chips cover important facts that inform the bid decision:
                    - State / region
                    - Specific instructions, e.g. workers must be TSA-checked,
                      licenses, bonds, mandatory pre-bid meetings, wage rules
                    - Restriction flag, e.g. "GSA Schedule holders only", small business set-aside
                    - Amended flag if the solicitation changed after posting

Behavior
 - Default sort: Est. value, highest first. Any column header can be clicked to re-sort.
 - Search box, plus filters for Municipality and Category.
 - Closed requests hidden by default (toggle to show).
 - Deadlines colored by urgency: 7 days or fewer = red, 14 days or fewer = orange.

3. DATA INTEGRATION (LATER)
---------------------------
 - SAM.gov Opportunities is the main feed. Start there.
 - USAspending.gov (free) can add pricing / competitor context.
 - SAM.gov Entity API can check vendor registrations.
 - State / city sites, DIBBS and eBuy need logins or scraping. Add one at a time.
 - Data shape used by the app is documented at the top of data.js.
 - Sample RFQ documents live in rfq-docs/ (fictional, one per sample request; the
   "shall" statements appear under the same section numbers the app cites). Real
   data will link to the actual solicitation document instead.

Things that trip up newcomers (from notes)
 - Deadlines are date, time and time zone, plus the agency's clock rules.
 - Solicitations change by amendment: diff and notify.
 - An RFQ may go only to GSA Schedule holders or a short list of vendors.
 - Lowest price does not always win; technical acceptability and responsibility count.
 - Past performance / CPARS ratings matter to repeat buyers.
 - Sources-sought notices are early signals.
 - Teaming agreements and subcontracting are central; model partners.
